# 照片缓存与同步后省电

## 行为

- 保存完全相同的照片 ID、顺序与微行动设置时，保留计划 revision 和轮播起始日；返回当前同步状态。
- 照片变化或顺序变化时更新计划，重新组装当前两日内容包。照片原图仍可能被读取，但已转换帧按内容哈希复用；相同图片即使属于不同上传 ID，也能在同一账户缓存中命中。
- 缓存只在私人 Worker 中使用。首次启用或算法更新后的首次转换需要生成缓存。
- 转换参数、Pillow 版本、prayer_device 源码或实际 film_convert.py 改变后，缓存键失效。修改缩放、旋转、配色或抖动参数时同步递增 FRAME_RECIPE。
- 缓存文件原子写入并验证长度与 SHA-256；损坏或读取失败重新转换，写入失败不影响下发。每账户独立目录，文件权限 0600。

## 配置与生效

Worker 默认缓存目录：运行目录 `.runtime/ritual-frame-cache/<accountId>`。可通过 `RITUAL_FRAME_CACHE_DIR` 指定私人持久目录，不要放到 public、dist 或共享静态目录。

Web/后台需经 GitHub main 推送触发 EdgeOne 构建。Worker 更新命令：先运行 `node scripts/install-photo-frame-cache.mjs --check`，再运行 `node scripts/install-photo-frame-cache.mjs`。安装器仅更新两个 Python 编译文件，并给现有 Worker 脚本加入缓存参数；保留其余运行时修复及 worker.env，自动备份后重启。小程序使用 `/Users/bessie/Desktop/命理唐卡/daily-prayer-web/miniprogram` 编译并上传 1.1.24，保留原目录中其他已完成的连接修复。

## 完成后断连

Web 和小程序使用一致的 SyncIdleRelease 判据。只有当前设备、当前计划、当前包的真实保存/刷新回执，或匹配当前包的 BLE 下载完成证据，才开始 30 秒保留期。仅手动确认不能触发。

保留期结束后断开蓝牙，停止查询和自动重连。保存新设置、生成新画、切换计划、断链或设备改变会取消计时；连接操作繁忙时延后。页面仍显示已保存状态，不要求为查看已保存画面重新连接。

不发强制关闭 Wi-Fi 命令。Wi-Fi 随设备现有空闲休眠逻辑关闭，任务繁忙或关闭自动休眠时不能保证固定断开秒数。本次不修改或发布固件。

## 验证边界

代码/模拟测试覆盖缓存命中、顺序调整、新图片、算法变化、损坏回退、缓存与无缓存内容包逐字节一致、保存幂等、30 秒释放、取消/延后及不自动重连。

真实手机蓝牙、小程序后台调度、画屏 Wi-Fi 休眠、电流与续航仍须实体设备验收，不能以构建或单测替代。
