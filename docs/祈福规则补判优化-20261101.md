# 祈福规则补判优化（2026-11-01）

## 已实现

引擎版本 rules-v3。方案选择继续由程序完成，不再要求每次补判整批重做：

- 没有会合成员关系的模型直接生成空判断；没有真实天干五合且没有调候需求时，天干与调候字段直接确定为空。
- 模型返回逐项校验，合法结果单独保留。重复模型、越界索引、不属于该组的关系、非法天干、重复占用真实天干均不能通过。
- 第二次调用只请求失败或缺失模型；天干调候字段与地支判断独立恢复。
- 每次返回后持久化局部进度。再次提交时从局部档案继续，未完成结果不会写成正式方案。
- 同日完整方案缓存按账号、完整输入、历法、稳定取用、此前历史、引擎与画风/目录版本隔离。修改出生资料或日期会重新计算。
- 后台失败记录带 diagnosticId、完成数、未决模型及天干调候未决状态；接口返回可关联编号，不向用户暴露命盘内部ID。

## 当前规则边界

| 判断 | 当前执行方式 | 未决时行为 |
| --- | --- | --- |
| 历法、来源实例、关系成员枚举 | 程序 | 历法错误阻断 |
| 三刑齐三支、自刑两实例、破关闭 | 已确认产品规则 | 不由模型改写 |
| 有效会合成员分配、残余冲与刑害 | 程序，输入必须是已验证有效会合 | 缺有效性判断不冒充成立 |
| 原局取用 | 已确认档案或模型补判 | 无可靠档案阻断 |
| 有效牵合、真实五合、当前调候满足 | 无成员时程序；其余逐项补判 | 保留已通过项，仅重试未决项 |
| 主尊、喜用配色、生肖筛选、天干景物、画风 | 程序 | 最终一致性失败阻断 |

当前代码采用三会、三合、六合的已确认产品排序；较旧技能参考存在不同表述，不能将旧版说明覆盖代码里已确认的产品政策。

## 尚不能宣称完成的部分

有效牵合、合化和调候满足的完整条件尚未全部形成审定决策表。不能用“成员齐全”替代，也不能将模型失败自动视为“不成立”。因此当前仍可能在关键条件未决时停止绘图；本次改善的是请求范围、恢复和可追踪性，不保证零模型或零失败。

局部未决时继续成画，需要先证明该项不影响实际盘判断、保护关系及最终已选要素；在此证明机制和规则条件补全前，默认继续阻断，不能直接删除生肖绕过校验。

## 后续顺序与验收

1. 从生产失败档案定位真实未覆盖条件，按实际盘/象征盘/调候分类形成案例集。本地代码不能证明某次线上失败的具体原因。
2. 为每条有效性条件补齐适用前提、排除项、证据、反例、版本和来源，先影子比较，再逐条替代模型。
3. 在可证明不影响选择的条件上启用局部省略，保存省略原因，不作“已化解”等结论。
4. 统计规则覆盖率、补判候选数、调用数、耗时、失败类别及恢复成功率；生产验证后再决定扩大规则范围。

回归涵盖索引错误的局部重试、连续缺项后的跨请求恢复、非法调候字段的独立重试、同日完整缓存、跨日与出生变更、账号隔离、会合竞争、刑害保留和天干保护。尚未部署，真实模型与线上网页链路仍需发布前验证。
