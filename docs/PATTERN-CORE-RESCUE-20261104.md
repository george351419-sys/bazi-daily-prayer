# 格局核心方向与救应分离

版本：rules-v12 / foundation-fgt-v8 / crosscheck-v4。

补充修订：[格局名称解析与补判反馈](FOUNDATION-FAILURE-FEEDBACK-20261104.md)。

## 问题与边界

旧字段 pattern_stems 同时接收格局顺逆用方向和成败救应。模型可能把壬水食神生财写成只取辛、庚印星；旧校验会指出冲突，但模型第二次坚持后仍可被采用。本次针对该结构性混用增加不可被复判跳过的校验。普通旺衰等解释性差异仍遵循一次复判、第二次合法输出为准，不混同为硬性计算结论。

本次未取得用户截图作品的专属链接，未读取该作品真实审计记录；以下案例由截图候选离线复现，不把复现结果当作线上两轮日志。

## 字段职责

- fuyi_stems：扶抑候选，身弱印比及逐干排除理由沿用原规则。
- pattern_stems：格局顺逆用的核心候选，进入七档交集排序。
- pattern_rescue_stems、pattern_rescue_reason：支持或救应的天干与具体条件，单独展示，不自动加入格局候选。若本来属于扶抑候选，仍可从扶抑档进入排序。
- pattern_route、pattern_route_reason：食神格的具体路线及独立依据。
- tiaohou_required_stems：调候规则映射，不受上述字段改名影响。

同一干可在扶抑与格局中分别具备独立作用；分开职责不意味着机械禁止不同方法取同一干。

## 食神格路线检查

按《子平真诠·论食神》的食神生财、制杀及就杀印分支分别核对，不把所有食神格无条件硬改成同一路线。

1. 未声明其他路线时按食神生财检查：核心至少有财星，且不混入印比。每个日主的财星由十神映射计算；壬水对应丙丁火，不是所有日主都取火。丙丁是否全取及其顺位仍由候选分析给出，校验不伪造精确顺位。
2. 食神制杀：核心为食神；必须原局有七杀并提供独立路线依据。
3. 弃食就杀印：核心为杀印，至少有印；必须原局有七杀、印星，并独立说明路线。仅“身弱”不足以证明改走此路线。
4. 不认识的食神路线、空核心、只在文字写生财但结构字段仍取印、缺救应理由，均明确提示。分支校验只是必要条件，不声称程序已完全证明成格。
5. 已明确确认的用户命例前提继续优先。其他格局仍有原有顺逆用比较器，本轮没有声称把全部传统格局条件实现为确定性判格。

古籍参考：[《子平真诠》影印本](https://upload.wikimedia.org/wikipedia/commons/f/fe/NLC416-11jh010455-35296_%E5%AD%90%E5%B9%B3%E7%9C%9F%E8%A9%AE.pdf)。顺逆用仅是方向，不能据一个标签断定整个命局适合增强财星。

## 复判、缓存与展示

首次发现冲突，反馈核心/救应差异以及规则对应的候选天干。保存初判、初次检查、复判、最终检查。合法复判仍可保留数值旺衰差异；核心与救应混用则拒绝归档，不继续绘图，不因“第二次坚持”强行采用。

旧 v6 及更早缓存迁移到 v7 时重新做 v3 检查。不得直接用旧版 model_second_retained 标记跳过新约束；需要补判时才调用模型。已完成旧作品保留原图与归档数据，说明页标记归档方向问题，不能把重排后的文字冒充当时已经按新规则作画。
