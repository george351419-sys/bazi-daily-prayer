# 调候规则、交集回退和模型二次复判

## 1. 调候映射

原典入口：[《穷通宝鉴》固定修订](https://zh.wikisource.org/w/index.php?oldid=2294674&title=穷通宝鉴)。日干和节气月决定基础查表位置，程序读取 [120格索引](../rules/tiaohou-index.json)。该索引整理自项目既有审阅稿，不能等同于逐条验证了古籍所有条件和各传本。

代码：[tiaohou-rules.mjs](../lib/tiaohou-rules.mjs)。保留具体天干、顺序、来源、基础候选、条件提示与未覆盖状态。原局需求与当天透干是否已经满足分开，缺项不会删除集合成员。

明确编码的节气分支：乙午夏至前后、乙酉白露/秋分、癸辰清明/谷雨。通过出生绝对时刻的上一节气判断，不按公历15日或农历月份。丁午火组合/有水分支、丁辰木组合先庚另有规则；成员条件沿用产品既有规则，不能据此宣称传统合化已成立。丁午未覆盖支路保留模型条件判断并标记，不能伪称规则结论。

尚未完整编码：所有“一派”“过旺”“水多”“金多”等程度条件、从格例外、水源根气与版本差异。基础索引是确定性候选入口，未覆盖条件仍保留复核标记。不得对外宣称全书所有例外均已自动化。并用组仅在明确记载的单元或已有确认档案中保存，不把任意两个候选一律设成必须并用。

## 2. 交集与回退

优先 F∩G → F∩T → G∩T，去重后取前两种五行。只有三组交集全部为空时，回退 F → G → T；仍保留具体天干顺序，不能用两个同五行干占满主次。若三法候选本身都空，则无可靠材料，不能制造喜用。只得到一种五行且交集非空时不自动补第二项。

回退必须存储 fallback_used、fallback_order，并在用户说明中展示。代码：[foundation-policy.mjs](../lib/foundation-policy.mjs)。

## 3. 格局顺逆用校验

原文：[《子平真诠·论用神》](https://www.donglishuzhai.net/chapter/3721.html)、[成败救应](https://www.donglishuzhai.net/chapter/3722.html)。月令财官印食按顺用入口，杀伤劫刃按逆用入口；财生官、印护官、食制杀、印制伤等作为方向检查，不把月令立格之神直接当成扶抑喜用。

格局取模型明确名称；未给出时仅用月令本气十神作为代理入口，标明 proxy，不冒称已排定最终格局。比较模型格局候选各干的十神角色与允许方向。透干成格、身强弱、印重用财、杀印相生等可能使基础检查不适用，因此冲突只触发复判，不直接强制覆盖模型。代码：[foundation-checks.mjs](../lib/foundation-checks.mjs)。

## 4. 数值旺衰算法调研

### 方案A：月令旺相 + 扶助/耗泄计数（本次选为辅助比较器）

源码固定版本：[Chinese-Metaphysics-Platform / analyzer.py](https://github.com/Sudo-Biao/Chinese-Metaphysics-Platform/blob/e1b96e0193a2aec44929df442924e9a4aba45418/core/bazi/analyzer.py)，配套月令表见同版本 core/constants.py。独立重写比较器，不安装或执行上游项目。

- 只看原局四柱。每个透干和藏干计1，日干自身也计入。
- 比劫、正偏印计扶助，其余食伤财官杀计耗泄。
- 完整三会/三合：生扶同类加3，克日主耗泄加3，日主克组合加2。两支组合仅按外部算法作部分计分；不回写本产品有效合、不用于解冲刑害。
- 得令且扶助≥耗泄，或得气且扶助>耗泄，记偏强；不得气且耗泄>扶助+1，记偏弱；其余记中和。月令旺相表沿用上游所注明的藏干气势派，不擅自调阈值迎合案例。
- 输出明细、月令状态、组合加分及最终分类。该分值不是概率，不代表经过实证验证的准确率。

局限：透藏等权、计入自身、未充分处理根气深浅、透干位置、合绊、强弱边界和特殊格。本次命例在此法下是扶助8、耗泄6、月令“死”，分类中和；与用户确认的偏弱并不一致，不能偷偷调整权重使它吻合。

### 方案B：日主五行占比 + 得令得地阈值（调研后未作为最终比较器）

源码：[whitefssw/bazi-calculator](https://github.com/whitefssw/bazi-calculator/blob/master/bazi_calculator.py)。其强弱分支使用日主五行占比、0.15/0.20/0.25/0.35等阈值、藏干根及得令条件。占比口径与方案A不同，不能将两者数值直接混成统一评分，也未找到可核验的准确率证明。

选A的原因是当前规则和分数分量容易审计，并非证明A更准。之后若改用别的算法，必须单独升级比较器版本并保存参数，不能混用旧缓存。

## 5. 冲突复判协议

1. 模型给初判；调候基础候选由映射规则给出。
2. 执行格局方向及原局数值校验。
3. 无差异，采用初判；有差异，将完整原局、初判、具体分量和冲突理由发回同一模型，要求一次语义复判和 review_reason。
4. 第二次有效输出为最终模型判断。即使仍有差异，也采用第二次结论，保存差异，不追加第三次同类语义复判。
5. 用户已明确确认的前提优先，不因分数触发模型改写。首次及复判共享总时限；服务失败或格式无效不能伪装成复判通过。格式修复/网络重试不等于新的语义裁决。

保留初判、规则检查、第二次结果、复判理由、最终采用来源。旧缓存只有已记录同版完整复判时才直接复用；否则按新协议补校验。网页会显示复核结论，完整内部记录用于核对，不把原始JSON直接展示给用户。代码：[foundation-review.mjs](../lib/foundation-review.mjs)。
