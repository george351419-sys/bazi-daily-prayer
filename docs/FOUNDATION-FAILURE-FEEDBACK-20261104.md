# 原局补判失败与响应校验反馈

版本：rules-v12 / foundation-fgt-v8 / crosscheck-v4。

## 本次实际取证的范围

用户报告一次“原局取用补判未完成”。在获得用户对指定出生资料调用既有 DeepSeek 文本服务的明确授权后，使用线上 v11 代码快照实调：两次文本请求后成功生成取用方案，未复现那一次终止。真实返回暴露了下面的解析缺陷；不能据此声称已读到原失败请求的账户日志，也不能声称该缺陷就是原失败的确定原因。

用户出生日期、时间、性别、原始模型响应不随本说明或测试提交；私人复现记录留在本机临时目录。回归测试使用独立合成命例。

## 发现与修复

### 1. 格局展示名称与结构类型混淆

旧解析仅支持固定短名，先去结尾“格”，再查表。模型返回“食神生财格（普通八格）”时未识别，悄悄退回月令本气。因而可能把同一候选按另一格局的顺逆方向比较，制造不必要的复判；也会漏掉本应适用的食神核心方向检查。

现在独立提供 pattern_type。pattern_name 用于可读说明；兼容旧档案中的括号和常见组合名称。类型与名称矛盾、显式名称未知时，反馈明确错误，不再静默降级为月令本气。未声明类型或名称的旧档案仍记录月令本气为代理入口，特殊格保留独立成立依据。

### 2. 约束检查未接入已有的响应修正重试

v11 在复判返回后才执行核心/救应和印比完整性硬校验。若复判返回仍违反字段约束，直接终止，未把这项具体错误反馈给模型修正。

现在复判结果在补判响应验证器中执行同一组约束；失败原因通过 validation_error 进入原有有界重试。首次判断、复判仍是两个语义阶段；最多额外一次响应修正，不开启无限命理投票，不要求模型迎合数值旺衰。原有 cross_check.model_calls 描述语义阶段，真实供应商请求可能因格式或约束修正超过两次。

仍不合法则停止绘图，保存 initial、initial_checks、rejected_second 至账户隔离的失败记录。服务端不会向客户端返回模型原文、账户资料或凭据。

### 3. 通用失败页面缺少定位编号

API 原来已有 diagnosticId，但旧小程序只展示 error 字符串而忽略编号。现在 error 中也附带不含出生资料的诊断编号，现有小程序无需更新包即可显示，之后可凭该编号定位失败。

## 缓存与验证

原局缓存升级 v8；迁移 v7 及更早档案时以 v4 检查重新确认格局名称与类型，不复用旧版校验标记跳过新约束。已完成旧画仍保留原图和当时的依据，不重新标成新版作品。

回归覆盖带括号格局名称、显式类型与名称冲突、未知类型、原有食神核心约束、复判收到具体校验错误后修正成功、仍错误时有界停止并保存两轮记录。完整构建及全量回归结果以本次发布记录为准。
