# 祈福方案规则引擎

版本：2026-11-01-rules-v4。默认入口为 `analyzeMapping` → `generateRuleMapping`。

## 已实现的链路

现有历法 → 稳定原局取用档案 → 当日条件检查 → 主题与主尊选择 → 79组生肖枚举与会合分配 → 天干意象 → 六色配色、解释、提示词 → 原有一致性校验。

手动 API、每日 Worker、次日祈福画准备均走此入口。规则路径不向 DeepSeek 请求完整画面方案，不用模型修复程序生成的方案。失败不会自动回退旧生成器。

主题未采用未经审定的十神能量评分：在已选愿望中按用户顺序、近期轮换选题；不虚构流日独有触发。主尊使用本地 v0.3 愿望专属理由，排除已暂停关联、五路群像和须另确认文化偏好的藏传候选。W02 冷启动按主喜用方位；历史轮换中优先避免连续同尊，再比较主次喜用匹配、同愿望/跨愿望次数及最近展示。其他主尊未编造五行标签。具体造像沿用主尊身份要求，未为没有审核模板的细节编造法器。

三会 > 三合 > 六合；同一来源地支不能重复分配，同支不同来源分别保留。高优先级关系无效不占成员。同等级保留相容分支，生肖只采用所有分支下都不增加残余冲刑害、不破坏关键关系且有改善的方案；同效取最少生肖。实际模型与每组象征模型均重新计算。刑害不因合自动删除；寅巳申、丑戌未齐三支论刑；子卯独立相刑；辰午酉亥两见自刑；破未启用。

天干先核已有有效五合及来干调候豁免，再选择来冲干的五合对象。新增意象不能冲其他已有天干或合走受保护关键干；多个新意象之间也检查冲合。必要调候并用组合不能只加入一部分。无合格响应的冲保留为未解决，不用调候装饰代替解冲。

## 模型与每日规则边界

## 2026-11-01 用户最新确认口径（优先于下文旧稿）

1. 三会、三合、六合成员齐全即有效牵合，不要求相邻，不另审月令或透干。凡能参与有效合的地支实例不论冲，即使该合因分配优先级未被采用；刑害仍保留。
2. 三会、三合按目标五行判断喜用作用；六合默认不推断合化五行，不标不利或关键五行关系。
3. 全部有利会合均保护。保留三会>三合>六合分配及同等级相容分支，用于生肖方案比较；不将分配限制重新作为冲恢复条件。
4. 真实天干五合配对出现即有效合绊，不要求相邻，不考虑争合，同一实例可以参与多组五合。冲的任一端参与五合即抑制该冲，不据此宣称合化。
5. 原局、大运、流年、流月、流日出现所需具体透干即满足该项调候；藏干不算。透干被合或被冲仍按出现计入；并用组合各干分别检查，缺项整体遵循原有并用保护。

上述每日条件由rules-v4直接执行，不调用模型。稳定原局喜用、调候需求及关键用干仍从已保存或已确认档案读取，首次缺档案时独立补判。

首次取用档案标记model_supplement或confirmed_profile；当日condition_assessment标记rules。已有可靠原局档案后，跨日无需DeepSeek也能生成完整画面方案。旧的bindings和bindings-partial缓存不再读取；旧画作不重写。

## 保存、失效与诊断

有账户时使用既有加密账户仓库，按账户分区保存：`prayer-rules/<owner hash>/<engine version>/foundation|mapping|failures/<signature>`。没有账户存储时只保留当前进程中有界缓存；匿名 API 按浏览器会话隔离，重启后不保证保留。

原局指纹含出生资料、时间校正和历法版本；当日条件由完整实际盘、原局档案及每个独立象征模型直接计算，结果随完整mapping保存。每日规则版本改变使旧映射失效；稳定原局继续使用独立v2档案版本。保存结果前校验；补判失败不会写入有效档案，故障诊断另存错误码、阶段、日期与输入指纹，不记录密钥或上游响应。最终方案附带规则版本、补判来源、79组候选的筛除结果、会合分配及未解决天干冲。

`PRAYER_FOUNDATION={signature,value}` 是服务端内部注入的已确认取用档案，指纹由 `natalFingerprint` 产生；不从公开请求体直接接收。`PRAYER_RULE_STORE` 为测试或自有持久化适配接口。无补判 Key 且确有缺项时返回 `rule_gap_model_unavailable`，不启动绘图。

## 回退与部署

默认 `PRAYER_ENGINE=rules`（留空同样为规则模式）。显式设置 `PRAYER_ENGINE=legacy` 才使用旧的整体 DeepSeek 生成器。此开关是上线回退入口，不是规则校验失败时的自动替代。

本地验证使用模拟补判，无真实付费调用。需要在目标环境部署构建产物后，新请求才会切换。既有作品和已排队旧版本任务不会被悄悄改写；每日工作流指纹含更新后的 RULE_VERSION，重新启用每日设置会取得新版本快照。
